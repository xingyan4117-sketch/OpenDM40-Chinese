##重要发现：v0.3.0 的两种常规刷机方式在这台机器上都不可用

实测结论，供后来者省时间：

|方式 |结果 |
|---|---|
| `PC can edit` 模式拷 `dm40*.bin` 到 U 盘，等表弹窗 | ❌ **不弹窗**。文件写进去了（写保护位已清），表不扫描根目录 |
| 关机时长按电源键 ~4s 进加载器 | ❌ **无反应**（官方手册"已知限制"里本就标注未经真机验证） |
| **USB SCPI `DBG:UPLOAD` + `DBG:UPDATE`** | ✅ **成功** |

所以：**要用 SCPI 方式**。

> **2026-11-01 更正**：上表第一行已经被推翻——U 盘复制法在真机上走通了
> （前提：设置里 U 盘 = **可写**、改完重插 USB）。它现在是仓库 README 推荐的
> 首选刷机方式，SCPI 直传降为备用。第二行（关机长按进加载器）仍然未经真机验证。

##刷机方法（Windows，实测可用）

###1. 准备

- Zadig：把 `USB\VID_1209&PID_D040&MI_00`（**Interface 0，仪器接口**，
不是 Interface 1 的存储接口）的驱动换成 **WinUSB**。
 装完设备管理器里该项状态变 OK、类别变 USBDevice。
- Python 3 + `pip install pyvisa pyvisa-py pyusb libusb-package`

###2. 上传并安装

上游 `tools/dm40dbg.py` 通过 Linux 的 `/sys/bus/usb/devices` 找设备，
**在 Windows 上跑不了**。用 `tools/upload_zh.py`（等价实现）：

```
python upload_zh.py IMAGE --update --wait 120
```

它会：
1. `DBG:UPLOAD:BEGIN <len>,<crc32>`
2. 分块 `DBG:UPLOAD:DATA <offset>,<232 字节二进制>`
3. `DBG:UPLOAD:END?` —— **表自己重新读取文件并校验 CRC-32**
4. `DBG:UPDATE` —— 清零加载器标记并复位，原厂加载器安装文件

约 7～10 秒传完，之后设备掉出 USB 约 1 秒，再出现即为新固件。

###3. 验证

```
python -c "import pyvisa; rm=pyvisa.ResourceManager('@py'); \
d=rm.open_resource(rm.list_resources()[0]); print(d.query('DBG:BOOT?'))"
```
加载器标记应等于镜像头部的前三个字（本补丁为
`0x0E6BF194 0x0009ADF4 0x000109A2`）。

或插 USB 看 `INFO/FIRMWARE.BIN` 的 SHA-256 是否等于所刷镜像。

###4. 截屏（可选）

上游 `dm40dbg.py shot` 同样只能在 Linux 上跑。Windows 用 `tools/shot.py`：

```
python shot.py out.png
```
读 `DBG:LCD?` 的 IEEE 488.2 块，rgb666，480×320，约 1 秒。

##Windows 上的构建环境备忘

`build.sh` 需要 bash、`python3` 和 `llvm-tools`。实测踩到的坑：

1. **bash 里 `RUSTUP_HOME`/`CARGO_HOME` 必须是 Windows 形式**（`C:/Users/...`），
 否则 rustup 找不到 settings.toml，报 "no default toolchain"，
 连带 `rustc --print sysroot` 返回空、`build.sh` 找不到 `llvm-objcopy`。
2. **PATH 里的目录必须是 MSYS 形式**（`/c/Users/...`），否则 bash 找不到 `rustc`。
3. `build.sh` 默认用 `$HOME/.rustup`（unix 路径）→ 必须显式 export 覆盖。
4. `tools/stack-depth/stackdepth.py` 的 `tool()` 用 `glob` 找 `llvm-objdump`，
 **没带 `.exe`**，Windows 上永远匹配不到 → 需补 `.exe` 后缀。
5. `tools/ci-tests.sh` 的 `ui-render` 用 POSIX `mmap`，**Windows 编不过**；
 `font-matrix` 可以跑，且正是验证字形数据的那一套。
6. `build.sh` 与测试脚本都期望仓库内有 `toolchain/rustup`、`toolchain/cargo`
 → 用目录联接指向真实安装即可。

一键脚本见 [`patch/build_zh.sh`](../patch/build_zh.sh)、[`patch/test_zh.sh`](../patch/test_zh.sh)。
